# Loca Loca — WinUI 3 + PostgreSQL (локально)

Новая настольная версия Loca Loca. Клиент переведён с Unity на WinUI 3, серверная часть остаётся локальной: ASP.NET Core + Npgsql + PostgreSQL.
Для этой версии Unity и Unity Hub больше не нужны: открывай решение `LocaLoca.sln` в Visual Studio. Старую Unity-папку можно оставить как резервную копию, пока WinUI-версия не будет проверена.

```text
WinUI 3 (.NET 10)
    │ HTTP 127.0.0.1:5181
    ▼
ASP.NET Core 10 (запускается вместе с приложением)
    │ Npgsql / PostgreSQL TCP 127.0.0.1:5432
    ▼
PostgreSQL (служба Windows на этом компьютере)
```

Не нужны VPS, платный хостинг, внешний IP, облачная база или аккаунты на сторонних сервисах. API слушает только `127.0.0.1`. Карта Leaflet/OpenStreetMap требует интернет для загрузки тайлов и библиотеки; каталог, профиль, посещения, фотографии и список желаний хранятся локально.

## Важно: существующая база уже настроена

Если ты ранее выполнила `tools/Setup-PostgreSQL.ps1` из Unity-архива и получила сообщение `PostgreSQL настроен для Loca Loca`, **не запускай настройку базы повторно без необходимости**. Новая версия использует ту же базу `loca_loca`, ту же роль `loca_app` и конфигурацию:

```text
%LOCALAPPDATA%\LocaLoca\server-config.json
```

Ни таблицы, ни пользовательские записи не переносятся и не удаляются. В новой версии API научился читать этот конфигурационный файл напрямую. Также исправлен повторно добавлявшийся SQL-параметр в операции сохранения посещения.

## Состав проекта

- `LocaLoca/` — клиент WinUI 3, XAML-интерфейс и HTTP-клиент.
- `Server/LocaLoca.Api/` — исходники локального ASP.NET Core API.
- `database/` — исходная схема, стартовые места и миграции.
- `tools/Setup-PostgreSQL.ps1` — настройка локальной БД для новой установки.
- `tools/Publish-LocalApi.ps1` — публикация серверного API в папку клиента.
- `tools/Build-Windows.ps1` — публикация API и сборка приложения Windows x64.

## Требования

- Windows 10 22H2 или Windows 11 x64.
- **Visual Studio 2026 (версия 18.0 или новее)** с компонентами **Разработка классических приложений .NET** и **Разработка приложений для Windows / Windows App SDK**. Для target framework .NET 10 это минимальная поддерживаемая версия Visual Studio; Visual Studio 2022 не поддерживает сборку проектов под .NET 10.
- .NET 10 SDK (стабильная версия, не Preview).
- Windows SDK 10.0.19041.0 или новее.
- PostgreSQL, уже установленный локально и запущенный как служба Windows.
- WebView2 Runtime для встроенной карты (обычно уже присутствует в Windows 11).

WinUI 3 и Windows App SDK восстанавливаются как NuGet-пакеты. .NET 10 должен быть установлен в стабильной версии 10.0.x (не Preview). В проекте закреплена стабильная версия Windows App SDK `2.6.4` (на дату подготовки — стабильный выпуск октября 2026 года).

## Первый запуск новой WinUI-версии

### 1. Публикация локального API

Открой PowerShell в корне распакованного проекта — там, где находятся папки `LocaLoca`, `Server`, `database` и `tools`.

Для Windows PowerShell 5.1, если система блокирует неподписанные скрипты, разреши выполнение только на время этого окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
```

Затем выполни:

```powershell
.\tools\Publish-LocalApi.ps1
```

После успешной публикации файл сервера должен находиться здесь:

```text
LocaLoca\Server\LocaLoca.Api.exe
```

API публикуется self-contained для Windows x64. На компьютере не требуется отдельный ASP.NET Core Runtime для его запуска.

### 2. Открытие в Visual Studio

1. Открой `LocaLoca.sln`.
2. Дождись восстановления NuGet-пакетов.
3. В конфигурации решения выбери `Debug` и платформу `x64`.
4. В списке профилей запуска выбери `Unpackaged`, если Visual Studio показывает несколько профилей.
5. Нажми F5.

При первом открытии Visual Studio может загрузить компоненты Windows App SDK из NuGet. Это обычное восстановление зависимостей.

### 3. Первый вход

При запуске окно приложения автоматически проверяет `http://127.0.0.1:5181/health`. Если API ещё не запущен, клиент запускает `LocaLoca.Api.exe` из папки `Server`, затем ждёт готовности PostgreSQL ограниченное время. Бесконечной блокировки UI нет.

После сообщения о доступной локальной базе можно создать аккаунт или войти в уже существующий. Аккаунты пользователей остаются в таблице `users` базы `loca_loca`.

## Функции WinUI-клиента

- регистрация и вход;
- каталог из PostgreSQL, поиск по названию/городу/стране и фильтр категории;
- карточка достопримечательности с описанием и исторической справкой;
- несколько независимых посещений одного места;
- дата, оценка 1–5, впечатления и заметки;
- добавление до 10 фотографий за сохранение (общий лимит API — 20 МБ), открытие и удаление фотографий;
- история посещений, редактирование и удаление записей;
- список «Хочу посетить»;
- добавление собственных точек нажатием на карту; личные точки можно запланировать или отметить посещёнными, заполнить дату, оценку, впечатления, заметки и прикрепить фотографии;
- статистика посещений, мест, городов и стран;
- интерактивная карта Leaflet/OpenStreetMap с маркерами каталога и личных мест;
- современный интерфейс в стиле Fluent: тёмная боковая навигация, светлая рабочая область, мягкие карточки, лаймовый акцент, русские подписи.

## Сборка Windows x64

Из PowerShell в корне проекта:

```powershell
.\tools\Build-Windows.ps1
```

Папка результата:

```text
Builds\Windows\
```

WinUI-клиент публикуется self-contained вместе с Windows App SDK Runtime. Размер результата будет заметно больше простого .NET-приложения — зато для обычного запуска пользователю не придётся отдельно устанавливать Windows App Runtime.

## Диагностика

- Если локальная база не подключилась, нажми «Повторить подключение» на экране входа. Если окно сообщает, что API не найден, повторно выполни `tools/Publish-LocalApi.ps1`.
- Если API доступен, но база не подключена, проверь службу PostgreSQL Windows и файл `%LOCALAPPDATA%\LocaLoca\server-config.json`.
- Для ручной проверки открой в браузере `http://127.0.0.1:5181/health`. Успешный ответ должен содержать `"apiConfigured": true` и `"databaseConnected": true`.
- Если NuGet не восстанавливается, проверь соединение с `api.nuget.org` и наличие Windows App SDK workload в Visual Studio Installer.
- Если карта пустая, проверь интернет и наличие WebView2 Runtime.
- При обновлении существующей базы примени миграцию один раз из корня проекта (при нестандартном порте или имени администратора подставь свои значения):

  ```powershell
  psql -h 127.0.0.1 -p 5432 -U postgres -d loca_loca -v ON_ERROR_STOP=1 -f database/04_migrate_user_map_places.sql
  ```

  После изменения исходников API выполни `tools/Publish-LocalApi.ps1`, чтобы обновить сервер, который запускается клиентом.

## Резервное копирование

База резервируется через pgAdmin (`Backup`) или `pg_dump`. Фотографии хранятся отдельно в `%LOCALAPPDATA%\LocaLoca\Photos`; для полного бэкапа нужно сохранить и БД, и эту папку.

## Ограничения проверки

Решение и API проверены командой `dotnet build`: обе сборки проходят без ошибок. Сборка WinUI выполнялась для Windows x64; предупреждение XAML о привязке оценки устранено. Это подтверждает компиляцию исходников, но не заменяет проверку запуска окна, подключения к PostgreSQL и публикации готовой версии на целевом компьютере.
