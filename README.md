# Loca Loca

**Loca Loca** — настольное приложение для ведения личного дневника путешествий. Оно помогает отмечать посещённые места на карте, сохранять даты, оценки, заметки и фотографии, а также вести список мест, которые хочется посетить.

## Возможности

- Регистрация, вход и работа с личным аккаунтом.
- Каталог достопримечательностей с поиском и фильтрацией.
- Списки «Посещено» и «Хочу посетить».
- Даты посещений, оценки, заметки и впечатления.
- Личные точки пользователя на карте.
- Фотографии посещений и личных точек; они хранятся в PostgreSQL и доступны при входе в тот же аккаунт с другого устройства.
- Карта и статистика путешествий.
- Изменение отображаемого имени и настройки интерфейса.

## Установка

### Для пользователя Windows

Loca Loca предназначено для Windows 10 версии 22H2 и Windows 11 x64.

1. Откройте раздел [Releases](https://github.com/teofobiaa/LocaLoca/releases) и скачайте установщик, если для проекта опубликован актуальный выпуск.
2. Запустите `LocaLoca-Setup.exe` и завершите установку.
3. Запустите приложение и зарегистрируйте аккаунт.

Установщик настраивает адрес облачного API и проверяет наличие WebView2. Пользователю не нужно вводить параметры Supabase или пароль PostgreSQL: клиент взаимодействует с сервером по HTTPS. Если готового установщика в Releases нет, его можно собрать по инструкции для разработчиков ниже.

### Для разработчика

Требуются:

- Windows 10 22H2 или Windows 11 x64;
- .NET SDK 10.0.100 или более поздняя версия в разрешённой ветке обновлений;
- Visual Studio с компонентами WinUI 3, Windows App SDK и Windows SDK;
- WebView2 Runtime;
- интернет для восстановления NuGet-пакетов;
- доступ к Supabase PostgreSQL — только если требуется запуск API с реальной базой.

Клонируйте репозиторий:

```powershell
git clone https://github.com/teofobiaa/LocaLoca.git
cd LocaLoca
```

Установите клиентские зависимости и задайте облачный адрес API:

```powershell
.\tools\Install-CloudDependencies.ps1
```

Откройте `LocaLoca.sln`, дождитесь восстановления пакетов, выберите `Debug / x64 / Unpackaged` и запустите приложение клавишей F5.

## Быстрый старт

1. Создайте аккаунт или войдите в существующий.
2. Найдите интересующую достопримечательность в каталоге.
3. Добавьте её в список посещённых или в «Хочу посетить».
4. Для посещённого места укажите дату, оценку, заметку и фотографии.
5. Добавьте собственную точку на карту, если нужного места нет в каталоге.
6. Откройте карту или статистику, чтобы просмотреть сохранённые данные.

Данные аккаунта синхронизируются через общий облачный API и PostgreSQL. Для доступа к ним на другом компьютере войдите в тот же аккаунт.

## Конфигурация

### Адрес API на Windows-клиенте

Клиент использует пользовательскую переменную окружения `LOCA_API_BASE_URL`, если она задана. В стандартной установке её настраивает установщик. Чтобы вручную задать адрес:

```powershell
[Environment]::SetEnvironmentVariable(
    "LOCA_API_BASE_URL",
    "https://<render-service>.onrender.com",
    "User"
)
```

После изменения переменной закройте и снова откройте приложение. Для возврата к локальному режиму разработки удалите переменную:

```powershell
[Environment]::SetEnvironmentVariable("LOCA_API_BASE_URL", $null, "User")
```

Если облачный адрес задан, клиент не переключается молча на локальный API при недоступности удалённого сервера.

### Серверные параметры

Облачный API получает секреты из защищённых переменных окружения Render:

- `LOCA_DB_CONNECTION` — строка подключения к Supabase PostgreSQL через Session Pooler и TLS;
- `LOCA_SESSION_SECRET` — секрет подписи сессий, не короче 32 символов.

Не помещайте эти значения в исходный код, клиент, установщик, GitHub Issues или коммиты.

При локальной разработке API может читать конфигурацию из `%LOCALAPPDATA%\LocaLoca\server-config.json`. Пароль в DPAPI-формате защищён областью `CurrentUser` и доступен только той же учётной записи Windows. Приоритет источников строки подключения описан в [инструкции по конфигурации API](Server/LocaLoca.Api/RENDER-DEPLOYMENT.md) и в коде сервера.

## Архитектура и хранение данных

- **WinUI 3** — настольный клиент Windows.
- **ASP.NET Core API** — серверная часть; поддерживает облачный режим Render и локальный режим разработки.
- **Supabase PostgreSQL** — общая база данных приложения. API подключается к ней через Npgsql.
- **Фотографии** — двоичные данные в столбцах `bytea` таблиц `photos` и `user_map_place_photos`. Они не зависят от временной файловой системы Render.

Собственная таблица `users` относится к учётным записям Loca Loca и не является Supabase Auth. SQL-файлы применяются администратором базы отдельно; приложение не запускает миграции автоматически.

## Разработка

### Сборка приложения

Из PowerShell в корне репозитория:

```powershell
.\tools\Build-Windows.ps1
```

Результат публикуется в `Builds\Windows`. Не перемещайте `LocaLoca.exe` отдельно от каталога `Server`: клиенту требуется расположенный рядом API.

### Сборка установщика

Требуются .NET 10 SDK, компоненты Windows App SDK/Windows SDK и Inno Setup 6.3 или новее:

```powershell
.\tools\Build-Installer.ps1
```

Результат: `Builds\Installer\LocaLoca-Setup.exe`.

### Тесты

Для запуска тестового набора требуются .NET 10 SDK и Docker Desktop с запущенным Linux-контейнерным движком:

```powershell
dotnet test Tests/LocaLoca.Tests.sln --configuration Release
```

Подробности, разделение уровней и границы тестовой среды приведены в [Tests/README.md](Tests/README.md), [плане тестирования](Tests/TEST_PLAN.md) и [каталоге сценариев](Tests/TEST_CASES.md).
