# Loca Loca

Настольное приложение для учёта путешествий: можно вести список посещённых мест, сохранять заметки и фотографии, а также отмечать точки на карте.

WinUI-клиент запускает локальный API на этом же компьютере. API может подключаться как к локальному PostgreSQL, так и к удалённой базе PostgreSQL. Интернет нужен для карты OpenStreetMap и для подключения к удалённой базе.

## Что нужно для запуска

- Windows 10 версии 22H2 или Windows 11, x64.
- Доступ к PostgreSQL: локальная служба или удалённая база с разрешёнными внешними подключениями.
- WebView2 Runtime для карты.

Для сборки из исходников также нужны Visual Studio 2026 (18.0 или новее) с компонентами разработки .NET и Windows App SDK, .NET 10 SDK и Windows SDK 10.0.19041.0 или новее. Используется стабильная версия .NET 10.

## Первый запуск с удалённым PostgreSQL

1. Убедись, что в панели хостинга созданы база и пользователь, а внешние подключения разрешены. Запиши точные имя базы, имя пользователя и требования к SSL. Не присылай пароль в чат и не добавляй его в репозиторий.
2. Открой PowerShell в корне проекта и запусти:

   ```powershell
   .\tools\Setup-Remote-PostgreSQL.ps1
   ```

   По умолчанию скрипт предлагает хост `pg4.sweb.ru` и порт `5433`. Введи данные из панели. Пароль запрашивается скрыто и строка подключения сохраняется в `%LOCALAPPDATA%\LocaLoca\server-config.json` — вне репозитория. Режим SSL по умолчанию `Prefer`; используй его требования хостинга, а не угадывай.

3. Убедись, что схема приложения создана именно в этой базе. Для новой пустой базы подключись к ней через PostgreSQL-клиент и выполни SQL-файлы из `database/` в порядке: `01_schema.sql`, `02_seed.sql`, `03_migrate_wishlist.sql`, `04_migrate_user_map_places.sql`. Скрипт `01_schema.sql` создаёт таблицы и не предназначен для повторного выполнения поверх уже существующих таблиц. Если `public.users` уже есть, сначала проверь наличие остальных таблиц; применяй только недостающие миграции.
4. Опубликуй локальный API (нужен .NET 10 SDK):

   ```powershell
   .\tools\Publish-LocalApi.ps1
   ```

5. Открой `LocaLoca.sln` в Visual Studio, дождись восстановления NuGet-пакетов, выбери конфигурацию `Debug`, платформу `x64` и профиль `Unpackaged`, если он отображается, затем запусти приложение клавишей F5.
6. Пока приложение запущено, открой `http://127.0.0.1:5181/health`. Успешный ответ должен содержать `"apiConfigured": true` и `"databaseConnected": true`. `127.0.0.1:5181` — локальный API на компьютере, это не адрес PostgreSQL-хостинга.

Для локального PostgreSQL вместо удалённого можно использовать `tools/Setup-PostgreSQL.ps1`; он предназначен именно для локальной службы и не настраивает базу хостинга.

## Важное ограничение безопасности

Этот режим — удобная настройка для разработки и личного тестирования, а не безопасная архитектура публичного сервиса. Пароль удалённой базы хранится в локальном конфигурационном файле, доступном учётной записи Windows пользователя; приложение-клиент может быть исследовано. Не используй пароль администратора базы: выдай отдельному пользователю только нужные права на базу приложения. Не открывай PostgreSQL для всех адресов, если хостинг позволяет ограничить IP. Для распространения приложения и общей синхронизации безопаснее размещать API на сервере, держать секреты только на сервере и подключать настольные клиенты к API по HTTPS.

Папка фотографий всё ещё хранится локально в `%LOCALAPPDATA%\LocaLoca\Photos`; удалённая PostgreSQL сама по себе фотографии между компьютерами не синхронизирует.

## Возможности

- регистрация и вход;
- каталог достопримечательностей с поиском и фильтром;
- список посещённых мест и «Хочу посетить»;
- даты, оценки, заметки и впечатления о поездках;
- фотографии к посещениям и личным точкам;
- статистика и карта с местами из каталога и собственными отметками.

## Сборка для Windows

Из PowerShell в корне проекта запусти:

```powershell
.\tools\Build-Windows.ps1
```

Готовая сборка появится в `Builds\Windows`. Клиент и API публикуются для Windows x64 вместе с необходимыми компонентами .NET и Windows App SDK.

## Если что-то не запускается

- **`127.0.0.1:5181` не отвечает.** Запусти Loca Loca; клиент запускает локальный API вместе с приложением. Если API-файл отсутствует, выполни `tools/Publish-LocalApi.ps1`.
- **API работает, но БД недоступна.** Проверь `%LOCALAPPDATA%\LocaLoca\server-config.json`, точные реквизиты БД, разрешение на внешнее подключение и SSL-режим хостинга.
- **Профиль не создаётся.** Убедись, что подключился именно к той базе, куда загружена схема, и что у пользователя БД есть право `INSERT` для `users`. Логин должен содержать 3–50 букв/цифр или символов `.`, `-`, `_`; пароль — не менее 6 символов.
- **Карта не отображается.** Проверь доступ к интернету и наличие WebView2 Runtime.
- **NuGet-пакеты не восстанавливаются.** Проверь доступ к `api.nuget.org` и установленные компоненты Visual Studio.

## Данные и резервная копия

При удалённой конфигурации данные приложения находятся в PostgreSQL хостинга. Фотографии хранятся отдельно в `%LOCALAPPDATA%\LocaLoca\Photos`. Для полной резервной копии сохрани дамп базы и эту папку с фотографиями.

Схема базы и SQL-миграции находятся в `database/`. После изменения исходников API запусти `tools/Publish-LocalApi.ps1`, чтобы обновить сервер, который использует клиент.

## Структура проекта

- `LocaLoca/` — WinUI-клиент.
- `LocaLoca/Assets/` — иконка приложения и изображения маскота.
- `Server/LocaLoca.Api/` — исходники локального API.
- `database/` — схема, начальные данные и миграции PostgreSQL.
- `tools/` — скрипты настройки базы, публикации API и сборки приложения.
