# Loca Loca

Настольное приложение для учёта путешествий: посещённые места, заметки, фотографии, личные точки на карте и список «Хочу посетить».

## Архитектура

- **WinUI-клиент** работает на компьютере пользователя.
- **ASP.NET Core API** поддерживает два режима: локальный `http://127.0.0.1:5181` для разработки и облачный HTTPS endpoint Render. В облачном режиме WinUI подключается к удалённому API и не запускает локальный сервер.
- **Supabase PostgreSQL** — общая удалённая база проекта. API подключается к ней через Npgsql и Supabase Session Pooler по TLS.
- **Фотографии хранятся в PostgreSQL** в двоичных столбцах `bytea` таблиц `photos` и `user_map_place_photos`. WinUI отправляет изображения через облачный API; файлы не зависят от локального диска Render и доступны при входе в тот же аккаунт с другого компьютера. В `%LOCALAPPDATA%\LocaLoca\Temp` создаётся только временная копия для открытия внешним просмотрщиком.

Регистрация, вход, каталог, посещения, оценки, заметки, wishlist, личные точки карты и их реляционные данные используют одну удалённую базу. Собственная таблица `users` приложения не является Supabase Auth.

## Быстрый старт для разработчика

Требования: Windows 10 22H2 / Windows 11 x64, .NET 10 SDK, Visual Studio с WinUI/Windows App SDK, интернет и доступ к Supabase PostgreSQL.

1. В Supabase Dashboard открой **Connect → Session Pooler**. Используй параметры именно своего проекта: host, port, database, username.
2. В корне репозитория запусти:

   ```powershell
   .\tools\Install-CloudDependencies.ps1
   ```

3. Установщик проверит WebView2 и автоматически настроит `https://localoca-api.onrender.com`. Адрес будет сохранён в `%LOCALAPPDATA%\LocaLoca\client-config.json` и в пользовательской переменной `LOCA_API_BASE_URL`. Вводить параметры Supabase и пароль PostgreSQL на клиентском компьютере не требуется: Windows-клиент работает через облачный API. При отдельном запуске `tools/Install-CloudDependencies.ps1` без параметра `-CloudApiUrl` можно настроить прямое подключение к Supabase для режима разработки. Пароль вводится скрыто и шифруется Windows DPAPI в области `CurrentUser`. В `server-config.json` сохраняются параметры подключения и DPAPI-зашифрованный пароль — открытая строка подключения с паролем не записывается. Конфигурация сохраняется вне репозитория в:

   ```text
   %LOCALAPPDATA%\LocaLoca\server-config.json
   ```

   Если в этом файле уже есть корректное подключение к удалённой PostgreSQL, скрипт сохранит его и не будет спрашивать пароль повторно; старый формат автоматически преобразуется в DPAPI. Локальную конфигурацию `127.0.0.1` скрипт предложит заменить облачной.

4. Открой `LocaLoca.sln`, дождись восстановления NuGet-пакетов, выбери `Debug / x64 / Unpackaged` и запусти проект клавишей F5.
5. Проверь доступность API: открой `http://127.0.0.1:5181/health` — ожидается HTTP 200. Для проверки подключения к Supabase и прав роли открой `http://127.0.0.1:5181/ready`; успешный ответ содержит `"apiConfigured": true` и `"databaseConnected": true`.

### Конфигурация и секреты

API читает строку подключения в следующем порядке:

1. переменная окружения `LOCA_DB_CONNECTION`;
2. переменная окружения `ConnectionStrings__LocaLoca`;
3. `ConnectionStrings:LocaLoca` из appsettings;
4. `%LOCALAPPDATA%\LocaLoca\server-config.json` (локальная разработка).

В репозитории нет пароля базы данных. Не добавляй connection string, пароль PostgreSQL, Supabase service-role key или другие секреты в `appsettings.json`, исходный код, issues или коммиты. Файл `server-config.json` находится в профиле Windows и исключён из Git. Пароль хранится в нём как DPAPI ciphertext (`CurrentUser`); локальный API расшифровывает его при запуске под той же учётной записью Windows. Старые конфигурации с `connectionString` поддерживаются для совместимости, а установщик мигрирует их в новый формат.

**Модель безопасности:** обычная установленная версия Windows-клиента обращается к Render API по HTTPS. Строка подключения PostgreSQL и секрет подписи сессий хранятся на стороне Render и не передаются клиенту. Только в режиме локальной разработки API запускается на компьютере разработчика и может подключаться к PostgreSQL напрямую; его пароль хранится в DPAPI-конфигурации профиля Windows. Не распространяй локальную конфигурацию и не встраивай DB-секрет в клиент.

## Облачный сервер Render

Облачная конфигурация находится в `main`: `render.yaml` (Render Blueprint) и
`Server/LocaLoca.Api/Dockerfile`. Отдельная feature-ветка уже объединена с `main`.

Подробная инструкция: [Server/LocaLoca.Api/RENDER-DEPLOYMENT.md](Server/LocaLoca.Api/RENDER-DEPLOYMENT.md).

Кратко:

1. В Render создай Blueprint из репозитория `teofobiaa/LocaLoca`, выбрав ветку `main`.
2. В `LOCA_DB_CONNECTION` добавь строку Supabase Session Pooler для роли
   `localoca_app.<project-ref>` с TLS.
3. В `LOCA_SESSION_SECRET` добавь случайный секрет длиной не менее 32 символов.
4. Дождись успешного деплоя: Render проверяет быстрый `/health`, а подключение к Supabase и права роли проверь отдельно через `/ready`.
5. На Windows-клиенте задай `LOCA_API_BASE_URL` равным HTTPS-адресу Render.

GitHub Actions проверяет сборку Docker-образа API. Render автоматически
разворачивает новые коммиты ветки `main`, к которой привязан Blueprint.

**Ограничения:** изображения сохраняются непосредственно в PostgreSQL (`bytea`),
поэтому они входят в размер базы и её резервные копии. За одну операцию разрешено
загрузить до 10 изображений общим размером не более 20 МиБ; поддерживаются JPG,
PNG, WEBP, BMP и GIF. Это удобно для текущего учебного проекта, но при росте
коллекции отдельное объектное хранилище будет экономичнее для базы данных.
Бесплатный Render-сервис засыпает после периода без запросов, поэтому первый
запрос может выполняться дольше. Подписанные сессии действуют 30 дней; секрет
подписи нужно сохранять неизменным между деплоями. Конфигурация предназначена
для учебного проекта, а не для production-нагрузки.

## Первый запуск на новом компьютере

1. Запусти `LocaLoca-Setup.exe`.
2. Установщик автоматически задаст облачный адрес Render и проверит WebView2. Параметры PostgreSQL и пароль на компьютере пользователя не запрашиваются.
3. Заверши установку и запусти приложение.
4. Зарегистрируй пользователя Loca Loca.

Установщик больше **не устанавливает локальный PostgreSQL**, не создаёт локальную службу и не создаёт отдельную базу на каждом компьютере. Все установки подключаются к общей Supabase PostgreSQL, если им указана одна и та же строка подключения.

Для сборки установщика нужны .NET 10 SDK, компоненты Windows App SDK/Windows SDK и Inno Setup 6.3 или новее:

```powershell
.\tools\Build-Installer.ps1
```

Готовый файл появится в `Builds\Installer\LocaLoca-Setup.exe`. Установщик включает WinUI-клиент, локальный API и сценарий настройки облачного адреса/WebView2; секреты и SQL-файлы в установщик не встраиваются.

## Удаление приложения

Удаляй Loca Loca через **Параметры Windows → Приложения → Установленные приложения**
или через стандартный деинсталлятор. Деинсталлятор удаляет установленную программу,
а также локальный каталог `%LOCALAPPDATA%\\LocaLoca`: облачную конфигурацию,
локальную конфигурацию PostgreSQL, временные копии фотографий и профиль WebView2 карты. Удаляется и старый каталог WebView2,
создававшийся предыдущими версиями рядом с `LocaLoca.exe`.

Пользовательская переменная `LOCA_API_BASE_URL` удаляется только тогда, когда
она всё ещё указывает на официальный API Loca Loca. Если пользователь заменил её
собственным адресом, деинсталлятор сохраняет это значение.

Общий Microsoft Edge WebView2 Runtime не удаляется, поскольку он может
использоваться другими приложениями. Данные учётной записи, посещения, личные
точки и фотографии в общей Supabase PostgreSQL также не удаляются:
деинсталляция одного компьютера не должна стирать облачные данные пользователя.
Для внешнего просмотра фотографий приложение создаёт временные копии в `Temp`;
они удаляются вместе с локальными данными приложения.

## Схема базы данных

SQL-файлы одной PostgreSQL-базы разложены по назначению в `database/schema/`, `database/seed/`, `database/migrations/` и `database/security/`. Порядок применения и различия между новой и уже существующей базой описаны в [database/README.md](database/README.md). Скрипты не запускаются автоматически приложением: их применяет администратор базы в Supabase SQL Editor.

Для новой базы достаточно актуальной схемы, стартового каталога и создания runtime-роли. Файлы миграций нужны прежде всего для обновления ранее созданной базы; не следует запускать скрипт создания роли повторно, если роль уже существует.

`tools/Export-AttractionsSeed.ps1` экспортирует справочный каталог из `LOCA_DB_CONNECTION` или локального `server-config.json` (поддерживаются старый формат и DPAPI). Для этого на компьютере разработчика нужны PostgreSQL Command Line Tools (`psql`).

## Возможности

- регистрация и вход в собственную таблицу пользователей приложения;
- изменение отображаемого имени на отдельной странице профиля без изменения логина для входа;
- отдельная страница поддержки с контактной почтой, ссылкой на репозиторий и релизы;
- каталог достопримечательностей с поиском и фильтром;
- список посещённых мест и «Хочу посетить»;
- даты, оценки, заметки и впечатления о поездках;
- фотографии к посещениям и личным точкам, хранящиеся в PostgreSQL и доступные на разных устройствах;
- статистика и карта с местами из каталога и собственными отметками.

## Сборка приложения

Из PowerShell в корне проекта:

```powershell
.\tools\Build-Windows.ps1
```

Готовая сборка появится в `Builds\Windows`. Клиент и локальный API публикуются для Windows x64 вместе с необходимыми компонентами .NET и Windows App SDK.

Если запускаешь приложение прямо из `Builds\Windows`, создай ярлык на `LocaLoca.exe`. Не перемещай этот файл отдельно: рядом должна оставаться папка `Server` с локальным API.

## Если что-то не запускается

- **API не отвечает.** Проверь, что `LocaLoca.Api.exe` находится рядом с клиентом в папке `Server`; клиент запускает его автоматически.
- **API запущен, но PostgreSQL недоступна.** Проверь интернет, параметры Supabase Session Pooler и `%LOCALAPPDATA%\LocaLoca\server-config.json`.
- **В `/ready` указано, что локальная PostgreSQL не поддерживается.** Повтори `tools\Install-CloudDependencies.ps1` и замени локальную строку подключения на Supabase.
- **Карта не отображается.** Проверь подключение к интернету и наличие WebView2 Runtime.
- **NuGet-пакеты не восстанавливаются.** Проверь доступ к `api.nuget.org` и компоненты Visual Studio.

## Данные и резервные копии

Реляционные данные находятся в удалённой Supabase PostgreSQL. Делай резервные копии базы из Supabase: бинарные данные фотографий входят в резервную копию вместе с записями. При этом размер PostgreSQL будет увеличиваться по мере загрузки изображений.

## Структура проекта

- `LocaLoca/` — WinUI-клиент.
- `LocaLoca/Assets/` — иконка и изображения маскота.
- `Server/LocaLoca.Api/` — локальный ASP.NET Core API с подключением к Supabase PostgreSQL.
- `database/` — схема, стартовые данные, миграции и права runtime-роли; см. [database/README.md](database/README.md).
- `Tests/` — unit, API and PostgreSQL integration tests; see [Tests/README.md](Tests/README.md).
- `installer/` — сценарий Inno Setup.
- `tools/` — настройка облачного подключения, публикация API и сборка приложения/установщика.
