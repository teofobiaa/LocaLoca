# Loca Loca

**Loca Loca** — настольное приложение для учёта путешествий. Сохраняйте посещённые места, планы, заметки и фотографии, просматривайте статистику и отмечайте места на карте.

Приложение состоит из WinUI-клиента и локального API. Клиент запускает API на этом же компьютере; API подключается к PostgreSQL — локальному или удалённому. Фотографии хранятся отдельно на компьютере.

## Возможности

- регистрация и вход;
- каталог достопримечательностей с поиском и фильтрами;
- списки «Посетил» и «Хочу посетить»;
- даты посещений, оценки, заметки и впечатления;
- фотографии посещений и собственных точек;
- статистика путешествий;
- карта достопримечательностей и личных отметок.

## Требования

Для запуска приложения:

- Windows 10 версии 22H2 или Windows 11, x64;
- PostgreSQL — локальный или удалённый, с разрешённым подключением;
- WebView2 Runtime для отображения карты.

Для сборки из исходников нужны стабильный .NET 10 SDK (не Preview/RC), Visual Studio 2026 (18.0 или новее) с компонентами разработки .NET и Windows App SDK, а также PostgreSQL с `psql` для локальной настройки базы.

## Быстрый запуск с локальным PostgreSQL

1. Клонируйте репозиторий и откройте PowerShell в его корне.
2. Установите и запустите PostgreSQL для Windows.
3. Настройте базу и сохраните конфигурацию подключения:

   ```powershell
   .\tools\Setup-PostgreSQL.ps1
   ```

   Скрипт создаёт или настраивает локальную базу `loca_loca`, применяет схему, начальные данные и миграции, затем сохраняет конфигурацию в `%LOCALAPPDATA%\LocaLoca\server-config.json`.

4. Откройте `LocaLoca.sln` в Visual Studio, дождитесь восстановления NuGet-пакетов, выберите конфигурацию `Debug` и платформу `x64`, затем запустите приложение.
5. При запущенном приложении проверьте `http://127.0.0.1:5181/health`. Успешный ответ должен показывать, что API настроен и подключён к базе данных.

## Подключение к удалённому PostgreSQL

1. Создайте базу и пользователя в панели хостинга и разрешите внешние подключения. Подготовьте схему базы: SQL-файлы находятся в `database/` — `01_schema.sql`, `02_seed.sql` и миграции `03_migrate_wishlist.sql`, `04_migrate_user_map_places.sql`. Для существующей базы проверьте её состояние и сделайте резервную копию перед применением SQL.
2. В корне проекта запустите скрипт и укажите реквизиты подключения из панели хостинга:

   ```powershell
   .\tools\Setup-Remote-PostgreSQL.ps1
   ```

   По умолчанию скрипт предлагает хост `pg4.sweb.ru` и порт `5433`. Пароль вводится скрыто; строка подключения сохраняется локально в `%LOCALAPPDATA%\LocaLoca\server-config.json`. Скрипт **не создаёт** базу или пользователя на хостинге и не загружает SQL-схему.

3. Опубликуйте локальный API (нужен .NET 10 SDK):

   ```powershell
   .\tools\Publish-LocalApi.ps1
   ```

4. Откройте `LocaLoca.sln` в Visual Studio, выберите `Debug` и `x64` и запустите приложение.
5. Проверьте `http://127.0.0.1:5181/health` и убедитесь, что API подключён к базе.

## Сборка Windows

Из PowerShell в корне проекта выполните:

```powershell
.\tools\Build-Windows.ps1
```

Скрипт публикует локальный API и WinUI-клиент для Windows x64. Результат появится в `Builds\Windows`.

## Данные и безопасность

- Конфигурация подключения к базе хранится в `%LOCALAPPDATA%\LocaLoca\server-config.json`. Файл содержит пароль; не публикуйте его, не добавляйте в Git и не передавайте другим людям.
- Фотографии хранятся локально в `%LOCALAPPDATA%\LocaLoca\Photos`. Удалённая база PostgreSQL не синхронизирует и не резервирует фотографии.
- При удалённой конфигурации данные путешествий находятся в PostgreSQL хостинга; настройте резервное копирование отдельно.
- Подключение удалённой базы — настройка для разработки и личного тестирования, а не безопасная архитектура публичного сервиса. Не открывайте локальный API в интернет и используйте SSL согласно требованиям вашего хостинга.

## Устранение неполадок

- **`127.0.0.1:5181` не отвечает.** Запустите приложение: оно запускает локальный API. Если API не стартует, повторно опубликуйте его командой `.tools\Publish-LocalApi.ps1`.
- **API запущен, но база недоступна.** Проверьте реквизиты в `%LOCALAPPDATA%\LocaLoca\server-config.json`, доступность базы, внешний доступ и режим SSL.
- **Не удаётся создать профиль.** Проверьте, что приложение подключено к базе с установленной схемой и пользователь БД имеет необходимые права.
- **Карта не отображается.** Проверьте подключение к интернету и наличие WebView2 Runtime.
- **Не восстанавливаются NuGet-пакеты.** Проверьте доступ к `api.nuget.org` и установленные компоненты Visual Studio.

## Структура проекта

- `LocaLoca/` — WinUI-клиент.
- `Server/LocaLoca.Api/` — исходники локального API.
- `database/` — схема PostgreSQL, начальные данные и миграции.
- `tools/` — скрипты настройки PostgreSQL, публикации API и сборки приложения.
