# Loca Loca

Настольное приложение для учёта путешествий: посещённые места, заметки, фотографии, личные точки на карте и список «Хочу посетить».

## Архитектура

- **WinUI-клиент** работает на компьютере пользователя.
- **Локальный ASP.NET Core API** запускается вместе с WinUI и слушает только `http://127.0.0.1:5181`. Этот loopback-адрес нужен только для связи клиента с API на том же компьютере.
- **Supabase PostgreSQL** — общая удалённая база проекта. API подключается к ней через Npgsql и Supabase Session Pooler по TLS.
- **Фотографии пока хранятся локально** в `%LOCALAPPDATA%\LocaLoca\Photos`. Записи о фотографиях находятся в общей PostgreSQL, но сами файлы не синхронизируются между компьютерами. На другом компьютере такие фотофайлы могут быть недоступны.

Регистрация, вход, каталог, посещения, оценки, заметки, wishlist, личные точки карты и их реляционные данные используют одну удалённую базу. Собственная таблица `users` приложения не является Supabase Auth.

## Быстрый старт для разработчика

Требования: Windows 10 22H2 / Windows 11 x64, .NET 10 SDK, Visual Studio с WinUI/Windows App SDK, интернет и доступ к Supabase PostgreSQL.

1. В Supabase Dashboard открой **Connect → Session Pooler**. Используй параметры именно своего проекта: host, port, database, username.
2. В корне репозитория запусти:

   ```powershell
   .\tools\Install-CloudDependencies.ps1
   ```

3. Скрипт проверит WebView2 и попросит параметры Supabase. Пароль вводится скрыто. Строка подключения сохраняется вне репозитория в:

   ```text
   %LOCALAPPDATA%\LocaLoca\server-config.json
   ```

   Если в этом файле уже есть корректное подключение к удалённой PostgreSQL, скрипт сохранит его и не будет спрашивать пароль повторно. Локальную конфигурацию `127.0.0.1` скрипт предложит заменить облачной.

4. Открой `LocaLoca.sln`, дождись восстановления NuGet-пакетов, выбери `Debug / x64 / Unpackaged` и запусти проект клавишей F5.
5. Проверь API: открой `http://127.0.0.1:5181/health`. Успешный ответ содержит `"apiConfigured": true` и `"databaseConnected": true`.

### Конфигурация и секреты

API читает строку подключения в следующем порядке:

1. переменная окружения `LOCA_DB_CONNECTION`;
2. переменная окружения `ConnectionStrings__LocaLoca`;
3. `%LOCALAPPDATA%\LocaLoca\server-config.json`;
4. `ConnectionStrings:LocaLoca` из appsettings.

В репозитории нет пароля базы данных. Не добавляй connection string, пароль PostgreSQL, Supabase service-role key или другие секреты в `appsettings.json`, исходный код, issues или коммиты. Файл `server-config.json` находится в профиле Windows и исключён из Git.

**Важно для учебного проекта:** настольный API подключается к PostgreSQL напрямую, поэтому пароль из локальной конфигурации доступен пользователю этого компьютера. Используй отдельную роль PostgreSQL с минимальными правами и передавай установщик только доверенным участникам. Для публичного продукта нужно разместить ASP.NET Core API на сервере и хранить DB-секрет только на сервере; клиенты должны обращаться к API по HTTPS, а не напрямую к PostgreSQL.

## Первый запуск на новом компьютере

1. Запусти `LocaLoca-Setup.exe`.
2. На шаге настройки укажи параметры Supabase Session Pooler. Пароль вводится скрыто и записывается только в локальный `server-config.json`.
3. Заверши установку и запусти приложение.
4. Зарегистрируй пользователя Loca Loca.

Установщик больше **не устанавливает локальный PostgreSQL**, не создаёт локальную службу и не создаёт отдельную базу на каждом компьютере. Все установки подключаются к общей Supabase PostgreSQL, если им указана одна и та же строка подключения.

Для сборки установщика нужны .NET 10 SDK, компоненты Windows App SDK/Windows SDK и Inno Setup 6.3 или новее:

```powershell
.\tools\Build-Installer.ps1
```

Готовый файл появится в `Builds\Installer\LocaLoca-Setup.exe`. Установщик включает WinUI-клиент, локальный API и сценарий настройки Supabase/WebView2; секреты и SQL-файлы в установщик не встраиваются.

## Схема базы данных

SQL-схема и миграции расположены в `database/`. Для нового Supabase-проекта администратор один раз выполняет SQL-файлы в Supabase SQL Editor в указанном порядке:

1. `database/01_schema.sql`
2. `database/02_seed.sql`
3. `database/03_migrate_wishlist.sql`
4. `database/04_migrate_user_map_places.sql`

Не выполняй `01_schema.sql` повторно поверх существующих таблиц. Для уже настроенного проекта не нужно повторно загружать схему и seed. Новые миграции следует применять один раз к общей базе до публикации соответствующей версии API.

`tools/Export-AttractionsSeed.ps1` экспортирует справочный каталог из базы, указанной в `server-config.json` или `LOCA_DB_CONNECTION`; для этого на компьютере разработчика нужен PostgreSQL Command Line Tools (`psql`).

## Возможности

- регистрация и вход в собственную таблицу пользователей приложения;
- каталог достопримечательностей с поиском и фильтром;
- список посещённых мест и «Хочу посетить»;
- даты, оценки, заметки и впечатления о поездках;
- фотографии к посещениям и личным точкам (файлы пока локальные);
- статистика и карта с местами из каталога и собственными отметками.

## Сборка приложения

Из PowerShell в корне проекта:

```powershell
.\tools\Build-Windows.ps1
```

Готовая сборка появится в `Builds\Windows`. Клиент и локальный API публикуются для Windows x64 вместе с необходимыми компонентами .NET и Windows App SDK.

Если запускаешь приложение прямо из `Builds\Windows`, создай ярлык на `LocaLoca.exe`. Не перемещай этот файл отдельно: рядом должна оставаться папка `Server` с локальным API.

## Если что-то не запускается

- **API не отвечает.** Проверь, что `LocaLoca.Api.exe` находится рядом с клиентом в папке `Server`; клиент запускает его автоматически.
- **API запущен, но PostgreSQL недоступна.** Проверь интернет, параметры Supabase Session Pooler и `%LOCALAPPDATA%\LocaLoca\server-config.json`.
- **В health указано, что локальная PostgreSQL не поддерживается.** Повтори `tools\Install-CloudDependencies.ps1` и замени локальную строку подключения на Supabase.
- **Карта не отображается.** Проверь подключение к интернету и наличие WebView2 Runtime.
- **NuGet-пакеты не восстанавливаются.** Проверь доступ к `api.nuget.org` и компоненты Visual Studio.

## Данные и резервные копии

Реляционные данные находятся в удалённой Supabase PostgreSQL. Делай резервные копии базы из Supabase и отдельно сохраняй локальные фотографии из `%LOCALAPPDATA%\LocaLoca\Photos`. Пока фотографии не перенесены в облачное объектное хранилище, копия БД не содержит сами фотофайлы.

## Структура проекта

- `LocaLoca/` — WinUI-клиент.
- `LocaLoca/Assets/` — иконка и изображения маскота.
- `Server/LocaLoca.Api/` — локальный ASP.NET Core API с подключением к Supabase PostgreSQL.
- `database/` — схема, стартовые данные и миграции общей PostgreSQL.
- `installer/` — сценарий Inno Setup.
- `tools/` — настройка облачного подключения, публикация API и сборка приложения/установщика.
