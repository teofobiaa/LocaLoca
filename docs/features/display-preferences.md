# Настройки отображения и независимость данных

## Назначение

Настройки отображения управляют только тем, что конкретный пользователь видит в интерфейсе Loca Loca. Они не являются командами удаления данных, изменением серверной выборки или настройками аналитики.

## Разделение ответственности

1. **Исходные данные** — профиль, страны, города, достопримечательности, посещения, фотографии и другие сохранённые записи. Скрытие не изменяет эти записи и связи между ними.
2. **Предпочтения отображения** — пользовательские настройки видимости блоков интерфейса, стран и отдельных элементов. Они применяются на клиентском уровне после получения данных и не меняют исходный набор данных.
3. **Аналитика и сбор данных** — отдельный контур с собственными настройками согласия/сбора. Изменение предпочтений отображения не включает, не отключает и не перенастраивает сбор аналитики.

## Обязательное поведение

- Скрытие блока убирает его из соответствующего представления, но не отключает его серверные операции, фоновые процессы или сбор данных.
- Скрытие страны исключает её из соответствующих визуальных представлений (например, списков/виджетов/карты, если настройка применима к ним), но не удаляет страну, посещения, точки, фотографии или статистические факты.
- Скрытие отдельного элемента интерфейса не удаляет связанный объект и не меняет его статус.
- Предпочтения принадлежат текущему аккаунту и не влияют на интерфейс других пользователей.
- Повторное включение отображения должно вернуть существующие данные без восстановления из резервной копии и без повторного импорта.
- При выходе из аккаунта предпочтения одного пользователя не должны применяться к следующему вошедшему аккаунту.
- Недоступность или повреждение файла/хранилища предпочтений не должна приводить к потере или изменению исходных данных. Безопасное значение по умолчанию — показывать элементы.
- Нельзя использовать скрытие как фильтр для аналитических SQL-отчётов, агрегатов или серверных метрик.

## Различие операций

| Действие | Меняет отображение | Меняет исходные данные | Меняет сбор аналитики |
| --- | --- | --- | --- |
| Скрыть блок | Да | Нет | Нет |
| Скрыть страну | Да | Нет | Нет |
| Скрыть элемент интерфейса | Да | Нет | Нет |
| Удалить объект через отдельную подтверждённую операцию | Возможно | Да, согласно правилам удаления | Не автоматически |
| Изменить настройку аналитики/согласия | Не обязательно | Нет | Да, согласно отдельной политике |

Удаление данных и изменение аналитических настроек должны оставаться отдельными явно названными действиями. Не следует объединять их с переключателями видимости.

## Требования к реализации

- Хранить предпочтения отдельно от таблиц с предметными данными и отдельно от настроек аналитики.
- Использовать устойчивые идентификаторы элементов, а не отображаемые названия, которые могут измениться или локализоваться.
- Предпочтения должны быть изолированы по пользователю; при хранении на клиенте использовать отдельный профиль/namespace для каждого аккаунта.
- Не добавлять фильтры видимости в API-запросы, SQL-запросы аналитики или агрегирующие запросы. Фильтрация применяется при построении UI.
- Если часть данных не загружена, скрытие не должно интерпретироваться как отсутствие или удаление данных.
- Синхронизация настроек между устройствами может быть добавлена отдельно, но не должна менять модель хранения исходных данных.

## Обязательные тесты

1. Скрытие блока меняет только состояние представления; исходные данные до и после операции идентичны.
2. Скрытие страны не удаляет страну, посещения, фотографии, личные точки и связи.
3. После повторного включения видимости существующие элементы снова отображаются без повторного создания.
4. Настройки одного пользователя не влияют на другого пользователя и не переносятся между аккаунтами на одном устройстве.
5. Изменение настроек отображения не вызывает запросов удаления и не изменяет параметры/состояние аналитики.
6. Аналитические агрегаты дают одинаковый результат при разных настройках отображения одного и того же пользователя.
7. Повреждённое или отсутствующее хранилище предпочтений приводит к безопасному отображению по умолчанию, а не к изменению данных.
8. Скрытые данные остаются доступными для отдельного явного действия пользователя (например, повторного включения отображения).
