# Приватность профиля и отношения пользователей

Реализовано в ветке `feature/friend-user-search`; настройки приватности дня рождения добавлены миграцией 022.

## Область текущей реализации

Настройки применяются отдельно к пяти полям профиля:

- отображаемое имя (`users.display_name`);
- аватар (`user_avatars`);
- страна проживания (`users.residence_country`);
- город проживания (`users.residence_city`);
- день рождения (полная дата `users.date_of_birth`, публично раскрываются только месяц и день).

Логин — технический идентификатор входа: публичный endpoint профиля его не возвращает. Тема оформления и локальные настройки клиента не являются сведениями публичного профиля. Посещения, заметки, фотографии посещений, избранное и личные точки карты не становятся доступными другим пользователям в рамках этой функции; они остаются в существующих пользовательских API с проверкой владельца. Полная дата рождения никогда не входит в публичную модель. Для профиля используется отдельная настройка `date_of_birth_visibility`: при разрешённом доступе сервер возвращает только месяц и день; год не раскрывается. Полная дата остаётся доступной только владельцу через личные endpoints и используется для возрастных рекомендаций.

## Категории доступа

Значения хранятся в `user_profile_visibility` и проверяются сервером:

- `private` — только владелец;
- `friends` — владелец и пользователи с подтверждённой взаимной дружбой;
- `registered` — любой пользователь с действующей авторизованной сессией LocaLoca.

«Заблокированные пользователи» — не вариант публикации. Блокировка — отдельный запрет, имеющий приоритет над любой настройкой. Если блок поставлен хотя бы в одну сторону, два аккаунта не видят профили друг друга и не могут создать дружбу, пока блок не снят.

Незарегистрированный и неавторизованный доступ не поддерживается.

## Начальные настройки

| Поле | Значение по умолчанию |
| --- | --- |
| Отображаемое имя | Все зарегистрированные |
| Аватар | Все зарегистрированные |
| Страна проживания | Только я |
| Город проживания | Только я |
| День рождения | Только я |

Миграция 015 создаёт настройки для существующих аккаунтов. Миграция 022 добавляет настройку дня рождения со значением `private` для уже существующих строк. Триггер и серверный helper обеспечивают безопасные значения для новых аккаунтов и старых строк.

## Модель дружбы и блокировки

`user_friendships` хранит одну запись на неупорядоченную пару аккаунтов. Меньший ID хранится в `user_low_id`, больший — в `user_high_id`. `requested_by_user_id` определяет отправителя ожидающего запроса; `status` принимает `pending` или `accepted`.

Повторный запрос от второго участника в ответ на ожидающий запрос автоматически подтверждает дружбу. Простое повторение запроса отправителем не создаёт дубликат. Принятие возможно только для входящего запроса.

Операции создания запроса, принятия, отмены, удаления дружбы и блокировки сериализуются транзакционной advisory-блокировкой PostgreSQL для канонической пары пользователей. Поэтому блокировка и отправка заявки не могут завершиться состоянием, в котором одновременно остаются активная блокировка и запись дружбы/ожидающей заявки.

`user_blocks` хранит одностороннюю блокировку. При блокировке в одной транзакции удаляется запись дружбы или ожидающий запрос для этой пары. Снятие блокировки не восстанавливает дружбу автоматически: участники должны отправить новый запрос.

## API

Настройки:
- `GET /api/me/profile/privacy` — получить свои настройки;
- `PUT /api/me/profile/privacy` — атомарно заменить настройки видимости всех пяти полей, включая `dateOfBirthVisibility`.

Профиль:
- `GET /api/users/{id}/profile` — получить только разрешённые поля чужого профиля; дата рождения представлена только месяцем и днём, если это разрешено настройкой;
- `GET /api/users/{id}/avatar?size=full|thumbnail` — получить аватар с той же проверкой приватности.

Поиск пользователей:
- `GET /api/users/search?login=<prefix>` — поиск по началу логина, без учёта регистра; требуется авторизация;
- поисковая строка должна содержать 3–50 допустимых символов; возвращается не более 20 аккаунтов;
- из выдачи исключаются текущий пользователь и аккаунты, заблокированные в любую сторону;
- логин возвращается всегда, отображаемое имя и наличие аватара — только согласно настройкам приватности;
- `relationshipStatus` принимает значения `none`, `outgoing_pending`, `incoming_pending`, `friends`;
- технический `userId` используется клиентом для операций дружбы и не должен отображаться в интерфейсе;
- действует распределённый лимит 30 поисковых запросов в минуту на IP;
- персонализированный ответ помечается `Cache-Control: private, no-store`.

Список друзей и заявок возвращает внутренний `userId` для адресации последующих API-вызовов и логин для отображения. Имя и наличие аватара выдаются только при разрешённой видимости. Для ожидающих заявок настройка `friends` не применяется: до принятия запроса доступны только поля с видимостью `registered`. Список блокировок возвращает логин, но не имя и аватар.

Дружба:
- `POST /api/users/{id}/friend-request` — отправить запрос;
- `GET /api/me/friend-requests` — входящие и исходящие ожидающие запросы;
- `POST /api/me/friend-requests/{id}/accept` — принять входящий запрос;
- `DELETE /api/me/friend-requests/{id}` — отменить или отклонить ожидающий запрос;
- `GET /api/me/friends` — список подтверждённых друзей;
- `DELETE /api/me/friends/{id}` — удалить из друзей.

Клиентский `LocaLocaApiClient` предоставляет методы `SearchUsersAsync`, `SendFriendRequestAsync`, `GetFriendRequestsAsync`, `AcceptFriendRequestAsync`, `CancelOrRejectFriendRequestAsync`, `GetFriendsAsync` и `RemoveFriendAsync`. Для блокировок доступны `BlockUserAsync`, `GetBlockedUsersAsync` и `UnblockUserAsync`. Для просмотра разрешённых полей чужого профиля и загрузки аватара используются `GetUserProfileAsync` и `GetUserAvatarBytesAsync`; недоступный или скрытый аватар клиент получает как `null`. Числовой `userId` не предназначен для отображения пользователю.

Блокировки:
- `POST /api/users/{id}/block` — заблокировать;
- `GET /api/me/blocks` — список заблокированных текущим пользователем;
- `DELETE /api/me/blocks/{id}` — снять собственную блокировку.

Все перечисленные endpoints требуют действующую сессию. Профиль и аватар возвращают 404 для отсутствующего или заблокированного в любую сторону аккаунта, чтобы не раскрывать состояние отношений через отдельный ответ.

## Серверная проверка

Сокрытие данных в интерфейсе не считается контролем доступа. Endpoint профиля выбирает каждое поле через SQL-условие видимости и учитывает владельца, статус дружбы и блокировки. Endpoint аватара выполняет самостоятельную проверку; URL изображения не является обходным путём. Ответ аватара помечается `Cache-Control: private, no-store`.

## Миграция и права

Для существующей базы применить миграции 021–022 в порядке manifest, затем выполнить `database/security/06_update_runtime_permissions.sql`. Миграция 022 добавляет приватность дня рождения и удаляет таблицу ручных контактов.

Если runtime-роль ещё не создана, выполнить `database/security/05_create_app_role.sql`, затем `database/security/06_update_runtime_permissions.sql` после миграций. Проверка `/ready` требует актуальную структуру `user_profile_visibility`.

Для новой базы использовать актуальный baseline и все миграции в порядке, указанном в `database/migrations/manifest.json`. Исторические baseline и миграции не переписываются.

## Текущие ограничения

В текущей реализации доступны поиск пользователей, просмотр разрешённых полей профиля, список друзей, входящие и исходящие заявки, блокировка и управление заблокированными аккаунтами. День рождения также поддерживает отдельную настройку аудитории и раскрывает только день и месяц.

Пользовательские списки аудитории не входят в миграцию 014 и не реализованы. Их проектное описание хранится в [будущем этапе пользовательских списков](../roadmap/future/user-defined-audience-lists.md).
